SUPER DESKTOP

A hidden overlay workspace for Hyprland / Omarchy — sticky notes and mini AI-terminal windows that slide in from the screen edges and vanish without a trace. Also a live view into your other PCs' workspaces and an optional encrypted bridge for your phone.

SUPER + SHIFT + Q

What is this?

A second, invisible desktop on top of your Omarchy workspace. Press the shortcut — notes and AI terminals glide in. Press it again — your desktop is completely clean. Everything keeps running in background tmux.

📝 Sticky notes

Click and type. Notes follow your Omarchy theme, autosave, drag, resize, and take group color tags.

💻 AI terminals

Live mini-terminals running coding agents. Iconify to 128×128, ghost-resize, expand to 80% of the screen.

🪄 True overlay

Hidden means hidden — nothing occupies Hyprland workspaces. Slide-in animations plus background blur.

🎨 Native theming

Colors, fonts, and terminal palette come from the active Omarchy theme and sync instantly on switch.

🎯 Hot corner

Park the pointer in the top-left corner for two seconds and the overlay toggles — no keyboard needed.

⌨ Your own shortcut

SUPER + SHIFT + Q out of the box — click Record in ⚙ Settings, press any combination, and it becomes the key that toggles the overlay.

🖥️ Remote sessions

Pair another PC and its consoles stream in live — real terminals, in colour, at the host's own positions, sizes and stacking order. Click and type into them.

📱 Phone linking

Pair an Android phone over an encrypted LAN/Tailscale bridge. Read terminals, type into them, get completion alerts and send image prompts. Optional.

Remote sessions — your other PCs live

Open the top-left This PC machine selector, choose Add a PC, and the other computer's workspace is drawn inside your overlay. Every visible console becomes a real terminal streaming that host's session output, in colour, as it happens.

↔ Two directions, one panel

Create and copy a one-time connection link to let another PC connect here, or paste a link created on the other PC to connect this PC there. The same Omarchy-styled panel does both.

🔐 Pinned & approved on the host

The certificate pin comes from the invitation, the six-digit code must match on both PCs, and approval always happens on the host. Unknown or denied peers are never saved.

🖥️ Host-faithful layout

Consoles keep the host's positions, sizes, stacking order and iconified state, uniformly scaled to fit your canvas and never enlarged.

⌨ Type into the host

Click a console and type — keystrokes, paste and Ctrl+C are written into that host session behind the same input guard as phone input. Keys are never replayed after a disconnect.

How pairing works

  1. On the host PC: ⚙ Settings → Android, start the bridge and generate an invitation, then copy its pairing link.
  2. On the viewing PC: open the machine selector → Add a PC, paste the link (a friendly name and address/port overrides are optional), and click Connect.
  3. Compare the six-digit code on both PCs and approve on the host. The peer is saved and its workspace opens automatically.
Both PCs must run a current build. After git pull, run ./rebuild.sh on each PC — it now restarts the separate harness-bridge process too, so an old bridge cannot keep serving port 8759. Existing approved peers do not need re-pairing. A host that says “Update and rebuild SUPER DESKTOP on the host” is serving an older bridge without terminal-pty-v1.

⚙ What the host advertises

workspace-snapshot-v1 (read-only snapshots/events) and terminal-pty-v1 (live attach). workspace-layout-v1 is deliberately not advertised yet, because remote layout mutations are still pending — a viewer only goes interactive when capabilities and desktopApiVersion match.

⏳ Current limits

Remote create, close, drag and resize stay on the host for now — the viewer shows pixels and sends input. At most eight consoles hold live streams (frontmost first); the rest keep their chrome with an explanation. Hiding the overlay releases the streams and showing it reconnects.

Endpoints

GET /api/v1/desktop/capabilitiesMachine ID, desktopApiVersion and the capability list.
GET /api/v1/desktop/workspaceComplete workspace snapshot from the host daemon.
GET /api/v1/desktop/events (WSS)Initial snapshot, then changed snapshots and 5-second heartbeats.
…/terminals/<card-id>/attach (WSS)Live terminal bytes: host→viewer output, viewer→host keystrokes.

All four require the existing paired-device bearer credential over HTTPS/WSS, and follow the same origin-rejection, expiry and revocation rules as every other bridge endpoint.

Phone / Android linking optional

An encrypted HTTPS/WSS bridge over LAN, Ethernet or Tailscale (port 8759, mDNS _omarchy-harness._tcp) lets a paired Android phone reach your SUPER DESKTOP terminals. There is no HTTP fallback and Tailscale is optional. It starts automatically with the daemon and can be stopped or restarted from ⚙ gear → Launcher connection.

💻 Operate terminals

List sessions and drive them — this is a remote terminal capability, not a read-only dashboard. Type into a session, and browse referenced files with PDF page previews.

🔔 Completion alerts

An Android per-terminal bell reports explicit Codex response completion, including while the phone UI is hidden, using an opt-in foreground monitor. Other harnesses have no verified adapter yet.

🖼️ Image prompts

Attach an image with ＋ and send it together with a prompt to an idle Codex terminal.

🔒 Per-phone access

Desktop QR verification, an explicit approval, and per-device revocation. Revoking on the desktop disconnects the phone's active sockets and invalidates its credential at once.

Secure pairing in five steps

  1. Desktop: ⚙ Settings → Android → Show secure pairing QR. The QR carries superdesktop://pair?data=…; its copyable link is expandable.
  2. Scan it with a camera that opens custom-scheme links and tap Open, or use Android → Bridges → Scan pairing QR, or paste the invitation. External links require explicit confirmation and never auto-approve.
  3. The phone requests approval with the QR's random 192-bit, single-use secret. Invitations expire after 300 seconds; approval requests after 120 seconds.
  4. Compare the displayed six-digit code and approve on the desktop. Device names are untrusted labels.
  5. The phone receives its own random 192-bit bearer credential, valid for 90 days. Android keeps credentials and pins in Keystore-backed encrypted storage; backups and device transfer are disabled.
Protocol v3 — desktop state stores SHA-256 credential hashes, never bearer credentials, and old HTTP-era credentials are invalidated on upgrade, so older phones must re-pair. Discovery and IP addresses never establish trust: the pin comes only from a physically verified QR. Read SECURITY.md before approving a device — an approved phone can operate your terminals.

Install (humans, 2 minutes)

# On your Omarchy machine, in a terminal:
git clone https://github.com/gladimdim/super-desktop.git ~/GitHub/super-desktop
cd ~/GitHub/super-desktop
./install.sh
# then press SUPER + SHIFT + Q

# for remote sessions, do the same on the second PC
# and keep both up to date with:
git pull && ./rebuild.sh
🤖 Are you an AI assistant installing this for your human? Don't improvise — the repo README has a dedicated step-by-step AI install section (preconditions, verification, hard rules, troubleshooting).

Useful commands

super-desktop toggle          # show / hide
super-desktop status          # visible? notes / terminals count
super-desktop add-note "Buy milk"
super-desktop add-term claude # + antigravity, codex, opencode, grok, reasonix, aider, shell
super-desktop reload-theme
super-desktop desktop-workspace # local card layout + revisions as JSON
./rebuild.sh                  # rebuild after updates (also restarts the bridge)

# remote sessions (PC-to-PC)
super-desktop peer-add --host 192.168.1.20 --name "Work laptop"
super-desktop peer-list                 # saved PCs (public metadata only)
super-desktop peer-workspace MACHINE_ID # host layout + card ids
super-desktop peer-attach MACHINE_ID CARD_ID --seconds 10 > console.raw
super-desktop peer-forget MACHINE_ID    # remove the local record (revoke on the host)

Paste the invitation as hidden stdin at the peer-add prompt — invitations are secrets and are never passed as command arguments. Outgoing peer credentials live in ~/.local/state/super-desktop/peers.json (0700 dir, 0600 file) and are not encrypted at rest.
